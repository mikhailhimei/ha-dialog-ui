# Звонки между Voice PE

Раздел **Звонки** — отдельный модуль HA Dialog UI. Он не включает радионяню и
не использует её сеансы. Совместно используются только ограниченный PCM-приёмник
и HTTP/WAV-поток с одноразовыми билетами. Ключи звонков хранятся отдельно в
`.storage/ha_dialog_ui.call_keys`; входящий TCP-порт — **8125** (радионяня — 8124).
В Docker bridge добавьте `8125:8125/tcp`; при `network_mode: host` проброс не нужен.
Адрес HA и ключи в прошивке вручную не задаются.

## Прошивка

На **обеих** колонках нужен отдельный пакет `modules/calls.yaml` из ветки
`feat/speaker-calls` репозитория Voice PE:

```yaml
packages:
  voice_pe:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: feat/speaker-calls
    files:
      - home-assistant-voice.yaml
      - modules/calls.yaml
    refresh: always
```

Сохраните свои `substitutions`, `esphome`, `wifi` и `api`. Для радионяни можно
дополнительно оставить `modules/baby-monitor.yaml`; звонкам он не требуется.
Колонки должны быть добавлены в интеграцию ESPHome в HA. Устройства только с
радионяней или обычные медиаплееры в список звонков не попадают.

## Использование

1. Откройте **Звонки**, выберите колонку, с которой звонить, затем получателя.
2. Нажмите **Позвонить**. На получателе прозвучит короткий повторяющийся сигнал.
3. Получатель отвечает верхней кнопкой либо действием HA `call_answer`.
   В интерфейсе можно открыть карточку получателя и нажать **Ответить**.
4. После ответа звук передаётся **одновременно в обе стороны** через HA.
5. **Положить трубку** или верхняя кнопка любой колонки завершают обе стороны.

Без ответа вызов завершается через 45 секунд. Закрытие окна или раздела
**не завершает** звонок: им можно управлять независимо из сценариев HA.
Разрыв потока, недоступность колонки и Mute завершают пару. После перезапуска
HA звонок не восстанавливается автоматически. Звонок и радионяня не могут
одновременно занимать одну колонку; существующий сеанс не перехватывается.

Микрофон звонка пассивно получает тот же обработанный звук, который уже получает
Assist, и не запускает/останавливает общий микрофон. Wake word и Assist не
выключаются. Конкретные команды не зашиты: назначьте действия сценариям своей
диалоговой интеграции. Ответ Assist идёт через обычный канал объявлений;
разговор — через канал media. Штатное приглушение media во время ответа Assist
сохраняется. Если запустить другое медиа на той же колонке, поток звонка может
быть прерван и пара завершится. Прежняя музыка автоматически не возобновляется.

## Действия для сценариев

```yaml
action: ha_dialog_ui.call_start
data:
  source_device_id: HA_DEVICE_ID_ПЕРВОЙ_КОЛОНКИ
  target_device_id: HA_DEVICE_ID_ВТОРОЙ_КОЛОНКИ
```

```yaml
action: ha_dialog_ui.call_answer
data:
  device_id: HA_DEVICE_ID_ВЫЗЫВАЕМОЙ_КОЛОНКИ
```

```yaml
action: ha_dialog_ui.call_end
data:
  device_id: HA_DEVICE_ID_ЛЮБОЙ_КОЛОНКИ_ПАРЫ
```

Укажите **device ID**, не entity ID. В визуальном редакторе действий доступны
селекторы устройств ESPHome. Сервер дополнительно проверяет поддержку прошивки.
Внутренний URL HA в настройках сети должен быть доступен обеим колонкам,
особенно при Docker bridge.

## Проверки и ограничения

Проверки используют HA Core, настоящий TCP/HTTP и синтетический PCM: два разных
потока одновременно доставляются в противоположные стороны. Проверяются
входящий ответ, отказ занятому устройству, завершение во время запуска,
разрывы, одноразовость билетов и выгрузка. UI проверяется на 1200 и 390 px.

```sh
.venv/bin/python -m pytest --asyncio-mode=auto tests/test_calls.py tests/test_monitor_runtime.py tests/test_monitor_ui.py tests/test_integration_lifecycle.py -q
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:calls
CHROMIUM_PATH=/usr/bin/chromium npm run test:monitor
```

Это экспериментальная реализация: качество подавления эха XMOS, распознавание
активационной фразы во время разговора, длительность работы и фактическая
задержка требуют проверки на двух физических Voice PE. Программные проверки
и компиляция этого не подтверждают. TCP и локальный HTTP не шифруют звук;
используйте доверенную домашнюю сеть. Публичный доступ к TCP-порту не требуется.
