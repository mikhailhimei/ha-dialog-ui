# Вкладка «Радионяня»

Серверная часть встроена в **HA Dialog UI**. Отдельная интеграция Voice PE Monitor,
карточка и ручное добавление источников не нужны. Обновите всю папку
`custom_components/ha_dialog_ui` (включая `static`) и перезапустите HA.

Если ранее установили Voice PE Monitor, отключите её записи **перед перезапуском**,
чтобы освободить порт 8124. После перехода отдельную интеграцию можно удалить.
HA Dialog UI автоматически находит ESPHome-колонки с действиями `monitor_source`,
`monitor_stop`, `monitor_configure`, создаёт отдельный ключ каждой колонке и
передаёт его через существующее авторизованное ESPHome API. Ключи хранятся
в `.storage/ha_dialog_ui.monitor_keys`, в браузер не отправляются.

Все колонки отправляют звук на один TCP-порт **8124**. При Docker
`network_mode: host` проброс не требуется; при bridge опубликуйте `8124:8124/tcp`.
Порт предназначен только для доверенной локальной сети: TCP-звук не шифруется.
Прослушивание с телефона доступно только через авторизованное соединение HA.

На каждой колонке нужен пакет:

```yaml
packages:
  voice_pe:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: experimental/baby-monitor
    files:
      - home-assistant-voice.yaml
      - modules/baby-monitor.yaml
    refresh: always
```

Сохраните свои `substitutions`, `esphome` и `wifi`. Не задавайте вручную IP или ключ.
Если раньше задавали `baby_monitor_port` отличный от 8124, удалите эту подстановку
и перепрошейте колонку. Колонки должны быть подключены к интеграции ESPHome в HA.

## Использование

1. Откройте **Радионяня** рядом с таймерами и будильниками. На телефоне пункт
   находится в меню разделов.
2. Выберите колонку-источник. В списке нет обычных медиаплееров: проверяются
   действия `monitor_source`/`monitor_stop`/`monitor_configure` в ESPHome. Отключённые устройства видны с отметкой «Нет подключения»,
   запустить их нельзя.
3. Выберите воспроизведение **на этом устройстве** (телефон/компьютер) или на
   другой совместимой колонке. Слушатели определяются по действиям
   `monitor_listen`/`monitor_stop`; источник нельзя выбрать собственным слушателем.
4. Нажмите **Старт**. На десктопе это окно, на мобильном — полноэкранный экран
   выбора. После подтверждения запуска показаны статус «Прослушивание активно»,
   кнопка остановки внутри окна и подсветка карточки активной колонки.
   Статус расположен сверху окна, рядом — подсказка о закрытии. Устройство
   воспроизведения выбирается из выпадающего списка.

## Что останавливает звук

- Закрытие окна выбора, в том числе крестиком, Escape и мобильной кнопкой
  «Назад», **не останавливает** сеанс.
- Выход из раздела «Радионяня», закрытие страницы или потеря её WebSocket-связи
  останавливает сеанс, **запущенный этой вкладкой**. Подписка принадлежит серверу
  HA: остановка не зависит от доставки запроса из `beforeunload` браузера.
- При закрытии вкладки во время запуска сначала отправляется остановка, затем
  дожидаются завершения запуска и повторяют очистку, чтобы микрофон не включился
  позднее. При потере связи с устройством немедленная остановка не гарантируется.
- Кнопка **Остановить** — явная команда, в том числе для сеанса из сценария HA.
  Для пары колонок она останавливает обе стороны встроенным сервером HA Dialog UI.
- Короткое нажатие верхней кнопки любой колонки пары и Mute работают так же,
  на уровне прошивки, независимо от интерфейса диалога.
- Смена приложения/блокировка телефона может приостановить браузерный звук:
  ограничения ОС на фоновое воспроизведение сохраняются. Переход вкладки в фон
  сам по себе не отправляет команду остановки.

## Сценарии HA остаются

Основные действия: `ha_dialog_ui.monitor_start_source`,
`ha_dialog_ui.monitor_start_listener` и `ha_dialog_ui.monitor_stop`.
Поля — `device_id`, а для слушателя также `source_device_id` и необязательный
`ha_url` (по умолчанию внутренний URL HA). Старые имена
`voice_pe_monitor.start_source`, `start_listener`, `stop` сохраняются как
совместимые псевдонимы, если отдельная старая интеграция их не зарегистрировала.

```yaml
sequence:
  - action: ha_dialog_ui.monitor_start_source
    data:
      device_id: ID_КОЛОНКИ_ИСТОЧНИКА
  - action: ha_dialog_ui.monitor_start_listener
    data:
      source_device_id: ID_КОЛОНКИ_ИСТОЧНИКА
      device_id: ID_КОЛОНКИ_СЛУШАТЕЛЯ
```

Уже запущенные источники и пары отображаются в разделе.

Если пользователь только открыл и закрыл раздел/окно для просмотра сеанса из
сценария, этот сеанс продолжает работать. Нажатие **Старт / Начать слушать**
передаёт управление выбранным сеансом вкладке: после её закрытия он остановится.
Для активной пары сначала нужна явная остановка; попытка занять её колонки
другим запуском не должна останавливать существующий сеанс. Две вкладки диалога
также не могут одновременно захватить один источник или его слушателя.

Для прослушивания на колонке внутренний URL HA должен быть доступен этой
колонке, особенно при Docker bridge. Адрес для устройств задаётся в настройках
сети HA; адрес внешнего браузера не используется как адрес аудиосервера.
Для браузера звук проходит через существующее авторизованное WebSocket-соединение.
Ключи отправки звука и одноразовые ссылки колонок в интерфейс диалога не выдаются.

## Проверки

```sh
npm ci
npm run build
npm run test:unit
CHROMIUM_PATH=/usr/bin/chromium npm run test:monitor
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
.venv/bin/python -m pytest --asyncio-mode=auto tests/test_monitor_runtime.py tests/test_monitor_ui.py tests/test_integration_lifecycle.py tests/test_timer_runtime.py -q
```

Зависимости Python — `tests/requirements.txt` и requirements из manifest интеграции;
для сборки `pyspeex-noise` в Linux можно задать `CC=gcc CXX=g++`.
Новые тесты проверяют фильтрацию совместимости, отсутствие секретов в ответах,
сохранение действий сценариев, выход во время запуска, выбор браузера/колонки,
сохранение сеанса после закрытия окна и остановку по закрытию раздела.
UI прогоняется в Chromium при 1200×900 и 390×900; аппаратное качество звука
и воспроизведение на реальных колонках требуют отдельной проверки.


## Восстановление после ошибки экрана

Ошибка отдельного раздела перехватывается внутри маршрутизатора: навигация
Home Assistant и меню разделов остаются доступными. Сообщение и кнопка повторного
открытия выровнены по центру видимой области, в том числе на телефоне. Переход
в другой раздел сбрасывает ошибку только этого экрана. При ошибке всей оболочки
показываются независимые ссылки на основные разделы и кнопка меню HA.
Проверка: `CHROMIUM_PATH=/usr/bin/chromium npm run test:recovery`.
